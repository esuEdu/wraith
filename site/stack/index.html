Under the hood

Stack and design

How wraith is built, and how it looks: one Go binary that talks to macOS through a short list of its own tools, and one palette, Heliotrope Haze, shared by the terminal and this site.

Stack

wraith is written in Go and ships as one binary, built for Apple Silicon and Intel at once. Most of the work is the standard library; seven modules come from outside, each for one job.

Go 1.26

The proxy is net/http and httputil.ReverseProxy; decryption is crypto/tls with a CA from crypto/x509; timing comes from httptrace; bodies and WebSocket messages are decompressed with compress/gzip and flate.

Bubble Tea v2 · Lip Gloss v2

The live view: Charm's terminal UI framework and its styling library, with charmbracelet/x/ansi to cut styled text to the screen's width.

cobra

Commands, flags and help, and the shell completion Homebrew installs for zsh, bash and fish.

yaml v3

config.yaml, read strictly (unknown keys are errors) and edited in place so your comments stay.

x/sys

The kernel's socket table (sysctl), to tell which process opened each connection without running a tool.

rsc.io/qr

The QR code an iPhone scans to join, drawn in the terminal with half blocks.

Build and release

  • Every pull request runs on macOS: gofmt, go vet and golangci-lint (with gosec), the tests with the race detector, CodeQL, govulncheck and a dependency review. Titles follow conventional commits.
  • Rules are tested by name. The behaviour wraith promises (R1.1, S2.6…) is written down, and each rule has a test named after it, such as TestS2_1_ListensOnLoopbackOnly; a check counts them.
  • A tag releases. v1.5.0 on main runs the checks again, then publishes the source tarball, its SHA-256 and a build provenance attestation you can verify with gh attestation verify.
  • Homebrew builds it on your Mac from that tarball, so there is no unsigned binary for Gatekeeper to stop. The tap follows new releases on its own.
  • This site is plain HTML, one stylesheet and a little JavaScript, with no framework and no build step, published from the repository's site/ folder by GitHub Pages.

Design principles

The terminal first

Everything happens in the terminal. The site draws the live view as it really looks, row for row, rather than inventing a screenshot.

One accent

Heliotrope violet marks what you can act on: keys, the selected tab, the badge. Pink is kept for the selection bar and highlights.

Color carries meaning

Green is a 2xx, yellow a 4xx, red a 5xx or an error, cyan a bypassed route. Nothing is colored only to decorate.

Calm by default

Secondary text is soft, rules are dim, and motion is slow and small. All of it stops when you ask for less motion.

Color

Heliotrope Haze is a dark violet background with soft pastels, after Rex's theme of the same name. The live view uses it as is; the terminal panels on this site use it in light and dark pages alike, because they show a terminal.

The terminal's own colors

With theme: terminal in config.yaml, the live view uses only the terminal's 16 colors, bold, faint and reverse, so it follows any terminal theme, light or dark. Cyan takes the accent's place; the meanings stay the same.

Mascot and icons

The mascot. A ghost, for a proxy that sits unseen between an app and the network. Lilac to heliotrope to pink, with a soft shine; it floats and blinks on the home page.

The icons. The wordmark uses the same ghost in the accent gradient. The browser tab gets a flat #c980f2 ghost with cut-out eyes and no background, bright enough that no browser puts a plate behind it.

Motion

  • The ghost floats over 4.5 seconds, blinks every few, and its shadow breathes with it; sparks twinkle around it.
  • The live view picture takes a new row every few seconds, and the selection follows it, as in wraith.
  • The connection diagram sends packets along its edges.
  • Cards and buttons lift by a few pixels on hover.

All of it is short and slow, and none of it runs when your system asks for reduced motion.
