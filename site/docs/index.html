Documentation

Everything wraith does, how to use it, and what it changes on your Mac.

Overview

wraith is a proxy you run from the terminal. While it runs, it is your Mac's HTTP and HTTPS proxy, and it does two things:

  • Inspect. It decrypts and shows traffic from one capture source: the iOS Simulator, one Mac app, one process, or everything. Traffic from anything else passes through untouched: never decrypted, stored or shown.
  • Route. Hosts on the bypass list are resolved and connected on the physical interface (Wi-Fi or Ethernet) instead of the VPN.

Requirements: macOS 13 or later on Apple Silicon or Intel. Xcode with at least one iOS simulator to capture simulator traffic.

wraith keeps its files in ~/.wraith. Set WRAITH_HOME to use another folder, for example a throwaway one for testing.

Install

Homebrew

wraith installs from its own tap. Homebrew builds it from the release's source on your Mac, so there is no Gatekeeper prompt. brew upgrade wraith gets new releases.

brew install esuEdu/tap/wraith
wraith version

From source

Needs Go (the repository pins its toolchain; go fetches the right one).

git clone https://github.com/esuEdu/wraith.git
cd wraith
make build
./wraith version

Uninstall

Take the CA out of simulators and the Mac first, then remove the program and its folder:

wraith ca remove
wraith ca untrust --mac
brew uninstall wraith
rm -rf ~/.wraith

Quick start

  1. Boot a simulator: xcrun simctl boot "iPhone 17" && open -a Simulator.
  2. Run wraith start. The first run creates ~/.wraith/config.yaml and the CA, puts the CA into every booted simulator, sets the system proxy, and opens the live view.
  3. Use your app in the simulator. Its requests appear as they complete, decrypted.
  4. Press q (or Ctrl-C). wraith stops and restores your proxy settings.

Check your setup at any time with wraith doctor.

Only want to listen? wraith start --no-system-proxy leaves the system proxy alone; point a client at 127.0.0.1:9090 yourself, for example curl -x http://127.0.0.1:9090 https://example.com.

Capture sources

The source decides which connections wraith decrypts and shows. Choose it with --source or source: in the config. Everything outside it is passed through untouched and never shown.

SourceCaptures
simulatorEvery booted iOS simulator. The default.
simulator:iPhone 17
simulator:<UDID>		One simulator, by device name or UDID.
app:Safari
app:com.example.shop		One app, by name or bundle id; also an app inside a simulator. A command-line tool matches by its executable name, e.g. app:curl.
pid:4242One process and every process it started.
device
device:192.168.0.23		Every iPhone or iPad you allowed, or one by its IP address. Needs --device; see iPhone and iPad.
allEverything that uses the system proxy, and every device you allowed.

How wraith knows who connected

For each new connection, wraith asks the kernel which process owns the client's socket, then walks its parent processes. A process running under launchd_sim belongs to a simulator, whose UDID comes from launchd_sim's arguments. An app is the outermost .app bundle on the process's own path, so Chrome's network helper (a bundle inside Chrome.app) counts as Chrome. A connection whose process cannot be identified is outside every source.

Pages loaded in a simulator's Safari or in a web view come from com.apple.WebKit.Networking, not from the app itself, and are labelled that way.

Change the source of a running wraith with s in the live view. It applies to new connections.

iPhone and iPad

A physical device on the same Wi-Fi as your Mac can use wraith as its proxy. Its traffic then leaves through your Mac, so it goes through your Mac's VPN, and the bypass list applies to it too.

wraith start --device

wraith also listens on your Mac's Wi-Fi address, for example 192.168.0.12:9090, and the live view shows a QR code with the steps (d shows it again later). The source is device unless you give --source.

  1. Scan the QR code with the iPhone's Camera and open the link. The device is now allowed, and the page shows the rest.
  2. Tap Download the certificate, install it from Settings › Profile Downloaded, then turn on full trust for wraith CA in Settings › General › About › Certificate Trust Settings. Once per device.
  3. In Settings › Wi-Fi, tap ⓘ next to the network, then Configure Proxy › Manual, and enter the server and port the page shows.

Turn the proxy off on the device when wraith is not running, or it loses its connection.

Who can connect

The QR code carries a key that is new each time wraith starts. A device on your Mac's network that opens the link with it is allowed, and remembered: on later runs it gets in without the code. wraith remembers it by its IP address on that network, in ~/.wraith/devices.json (macOS does not show wraith the network's hardware addresses), and forgets it after 30 days unseen. At a new address, it needs the QR code again. wraith devices list shows the remembered devices and wraith devices forget <ip|all> removes them. Another device that later gets a remembered address from the router could use wraith too; forget devices you no longer use.

wraith listens on that one Wi-Fi address only, never on every address, and only while --device is on. It hands the CA certificate only to allowed devices; its private key never leaves the Mac.

When it does not work

  • The device and the Mac must be on the same network. Guest and many office networks keep devices apart; a phone hotspot or home Wi-Fi works.
  • If the macOS firewall blocks wraith, the live view says so: set wraith to “Allow incoming connections” in System Settings › Network › Firewall › Options.
  • A VPN on the device can send its traffic away from your Wi-Fi; turn it off while you use wraith.
  • Apps that pin their certificates fail when decrypted. Add their hosts to no_decrypt (n in the live view).

HTTPS and the CA

wraith decrypts HTTPS with its own certificate authority, created on your Mac on first use in ~/.wraith/ca/. The folder is mode 0700 and the key 0600; wraith refuses to start if either is wider. The key never leaves the folder. The CA is valid for two years; wraith doctor warns 30 days before it expires.

Simulators

wraith start installs the CA into every booted simulator, and into each simulator booted while it runs, within a few seconds. wraith ca install does it on demand; wraith ca remove takes it out of every simulator again, booted or not, without touching other certificates. A booted simulator may keep trusting a removed CA until it restarts.

The Mac

By default the Mac does not trust the wraith CA, so Mac apps in the source are passed through and shown, but not decrypted. To decrypt them:

wraith ca trust --mac      # explains what this allows, asks, then macOS asks for your password
wraith ca untrust --mac    # undo

Think before trusting. While the Mac trusts the CA, wraith can decrypt HTTPS from every app that uses the system trust store, and anyone who obtains ~/.wraith/ca/ca.key could impersonate any website to your Mac.

When a connection is not decrypted

A tunnel that wraith passes through shows as tunnel in the log, with the reason:

  • on no_decrypt: the host matches the no_decrypt list (by default *.apple.com and *.icloud.com). Add a host from the live view with n.
  • certificate rejected: the client refused wraith's certificate, because the app pins its certificates or the device does not trust the wraith CA yet. That attempt fails, and wraith passes the host through for that client for 30 seconds, then tries again; after a third refusal it stops trying for the session. So a device you have just set up is decrypted again within half a minute, and an app that pins fails only a few times. Add a pinned host to no_decrypt (n) to pass it through from the start.
  • the client sent nothing: the client opened a tunnel and stayed silent for 10 seconds, usually a browser's preconnect.
  • not TLS: another protocol over CONNECT, such as SSH.
  • this client is not decrypted: a Mac app while the Mac does not trust the CA.

wraith always verifies the real server's certificate (TLS 1.2 or later). For a local development server with a self-signed certificate, name it: wraith start --insecure-upstream dev.local.test.

Rotate the CA with wraith ca rotate: it removes the old one from simulators and installs the new one into booted ones. Export the certificate (never the key) for a device you set up by hand with wraith ca export ca.pem.

VPN bypass

Hosts on the bypass list skip the VPN. wraith resolves them with DNS sent over the physical interface (its own DHCP resolver first, then public resolvers; never the VPN's DNS), then connects with sockets bound to that interface: IPv6 addresses first, IPv4 next. macOS keeps a route for the interface even while a VPN owns the default one.

wraith bypass add api.partner.example '*.corp.example.com'
wraith bypass list
wraith bypass rm '*.corp.example.com'
  • api.example.com matches that host only; *.example.com matches its subdomains, not example.com itself. The most specific rule wins.
  • Bypass applies to every connection that reaches wraith, whatever the capture source.
  • The list lives in config.yaml; the commands edit it and keep your comments. b in the live view adds the selected host and applies it at once.
  • The interface is detected (the first en* that is up, has an address and its own default route). Override it with --iface en1 or interface: in the config.

Fail closed

If a bypassed host cannot be reached on the physical interface, the connection fails and shows as failed. It is never sent through the VPN instead.

When your VPN gets in the way

Some VPNs refuse sockets bound outside the tunnel for IPv4 but leave IPv6 alone. Then only hosts with an IPv6 address can be bypassed. wraith doctor --host <host> shows each address family separately:

info  IPv6 2001:db8:10::1: normal path via en0 from 2001:db8::5; bypass via en0 from 2001:db8::5
info  IPv4 203.0.113.10: normal path via utun6 (a VPN tunnel) from 10.203.1.19; bypass fails (connect: network is unreachable)
ok    bypass works for api.partner.example over IPv6

Check your company's policy. Sending traffic around a work VPN can break it, even when it works technically.

Live view

wraith start opens the live view when your terminal is interactive. Each row shows the time, the source, the status (tun for a tunnel passed through, with why after its address: no_decrypt, certificate rejected, idle…), the method, the route and the URL. The list follows new traffic unless you scroll up. It draws in the Heliotrope Haze theme, a dark violet palette; set theme: terminal in the configuration to use your terminal's own 16 colors instead, so it follows your terminal theme, light or dark.

KeyDoes
↑ ↓ · j kMove. g / G jump to the oldest / newest.
EnterDetails, with a Response tab and a Request tab, each showing headers and body. Tab (or ← →, 1 2) switches tabs. gzip and deflate bodies are decoded and JSON is pretty-printed and colored, for display only; traffic is forwarded as sent. In the details, b copies the body of the tab on screen (decoded), h its headers, u the URL and c the request as curl; copied headers and URLs are redacted like exports. Esc goes back.
/Filter: every word must appear in the source, method, URL, status or route. Esc clears it.
sPick the capture source for new connections from a list: all, every booted simulator, each booted simulator (with its iOS version and whether it has the CA) and each running Mac app. Type to narrow the list; text that matches nothing is used as typed, e.g. pid:1234.
dWith --device: show the QR code and steps to set up an iPhone or iPad again. Esc goes back to the flows.
bAdd the selected host to the bypass list (saved and applied at once).
nAdd the selected host to no_decrypt.
cCopy the request as a curl command, secrets redacted.
eExport every flow as HAR to wraith-<time>.har in the current folder, redacted.
xClear the list.
q · Ctrl-CQuit and restore the system proxy.

Log mode and JSON

With --log, or when the output is not a terminal, wraith prints one line per flow instead:

12:04:31 [sim iPhone 17 · Shop] GET https://api.shop.example/v2/cart?page=2 200 1.2 kB 34ms vpn
12:04:32 [curl] CONNECT example.com:443 tunnel vpn (passed through: this client is not decrypted …)
12:04:33 [curl] CONNECT blocked.example:443 502 failed (bypass failed: …)

Lines carry the time, source, method, URL, status, size, duration and route, never a header value or a body. Query parameters named like secrets are redacted and query strings are cut after 64 characters. --log --json prints the same fields as one JSON object per line.

Export

Captured flows live only in the running wraith's memory (the last 5,000 by default, bodies kept up to 1 MB each). Save them while it runs:

wraith export --har flows.har
  • The file is HAR 1.2: open it in a browser's network panel or any HAR viewer. Each entry notes its source and route.
  • Authorization, Cookie, Set-Cookie and *token* headers, and query parameters with those names, are replaced by REDACTED. --no-redact keeps them.
  • The file is written with mode 0600 and never over an existing one without --force.
  • export talks to the running wraith over a Unix socket in ~/.wraith that only you can open. When wraith is not running there is nothing to export.

Configuration

~/.wraith/config.yaml is created with these defaults on first run. Command-line flags override it. Unknown keys and invalid values are refused when wraith starts.

port: 9090                  # proxy port on 127.0.0.1 and ::1
source: simulator           # all | simulator | simulator:<udid|name> | app:<name|bundle-id> | pid:<pid>
interface: auto             # physical interface for bypassed hosts: auto, or en0, en1, ...

capture:
  max_flows: 5000           # flows kept in memory
  max_body_bytes: 1048576   # bodies above this are truncated

bypass: []                  # hosts that skip the VPN, e.g. ["*.example.com", "api.partner.io"]

no_decrypt:                 # always passed through, never decrypted
  - "*.apple.com"
  - "*.icloud.com"

export:
  redact_headers: [Authorization, Cookie, Set-Cookie, "*token*"]

theme: heliotrope-haze      # live view colors: heliotrope-haze, or terminal for its own palette

Security and privacy

  • wraith listens on 127.0.0.1 and ::1 only and closes any other peer before reading from it. With --device it also listens on the Mac's Wi-Fi address, and lets in only devices on that network that opened the setup link from its QR code.
  • It runs as you and refuses to run as root; macOS asks for permissions itself when it needs to.
  • Captured traffic stays in memory and is gone when wraith stops. Only exports you ask for write files, mode 0600, redacted by default.
  • Log lines never contain header values or bodies.
  • Every upstream certificate is verified, except for hosts you name with --insecure-upstream.
  • wraith makes no network calls of its own: no telemetry, no update checks.
  • Your proxy settings are saved before any change and restored on exit, Ctrl-C, SIGTERM and after a crash.

Report a vulnerability privately through GitHub, never in a public issue. See the security policy.

Troubleshooting

Start with wraith doctor; it names what is wrong and how to fix it.

Websites stopped loading after wraith exited

The system proxy still points at wraith (for example after a forced quit). Run wraith stop: it restores your settings even when wraith is not running.

An app's requests do not appear

  • Is it in the source? The default is simulator; Mac apps need app:<name> or all.
  • Does it use the system proxy? Apps that ignore proxy settings bypass wraith completely.
  • A web page in the simulator shows as com.apple.WebKit.Networking, not as the app.

A host shows as tunnel instead of being decrypted

The line says why: no_decrypt, pinned, idle preconnect, not TLS, or a Mac app the Mac does not trust the CA for. See When a connection is not decrypted.

The simulator does not trust the CA

Run wraith ca install with the simulator booted, then restart the app. wraith doctor lists each booted simulator and whether it trusts the CA.

A bypassed host fails

Run wraith doctor --host <host>. If the bypass fails over IPv4 and the host has no IPv6 address, your VPN blocks bypassing for that host.

Port 9090 is in use

Use another one: wraith start --port 9191, or set port: in the config.

Limits

  • macOS only. Physical iPhones and Android devices are not supported.
  • Apps that ignore the system proxy are neither captured nor bypassed.
  • wraith shows traffic; it does not edit it (no breakpoints, rewrites or map-local).
  • HTTP/3 (QUIC) is not proxied; clients fall back to HTTP/2 or HTTP/1.1 through the proxy.
  • Bypass goes out on the physical interface only; SSH or WireGuard routes are not supported.
