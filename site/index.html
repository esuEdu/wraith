Terminal proxy for macOS

See your iOS app's HTTPS. Route chosen hosts around your VPN.

wraith decrypts traffic from the iOS Simulator, an iPhone or iPad on your Wi-Fi, one Mac app or one process, and passes everything else through untouched. Hosts you name skip the VPN and go out on Wi-Fi or Ethernet. All of it from the terminal.

$ brew install esuEdu/tap/wraith
Quick start Read the docs

Homebrew builds it from source on your Mac. Release notes

Two jobs, one proxy

wraith sets itself as your Mac's proxy while it runs and puts your settings back when it stops, even after a crash.

Inspect one source

Pick what you want to see; nothing else is decrypted, stored or shown.

  • simulator: every booted simulator (the default), or one by name or UDID
  • app:Safari, app:com.example.shop: one Mac app
  • device: an iPhone or iPad on your Wi-Fi, set up once by scanning a QR code
  • pid:4242: one process and its children
  • all: everything that uses the system proxy

HTTP/1.1 and HTTP/2, headers and bodies, in a live view, as log lines or JSON, and exported as HAR.

Route around the VPN

Hosts on the bypass list are resolved and connected on the physical interface instead of the VPN tunnel, IPv6 first.

$ wraith bypass add api.partner.example
wraith: added api.partner.example
$ wraith doctor
ok    interface: en0 (192.168.1.20, 2001:db8::5)
info  IPv4: normal path via utun6 (a VPN tunnel)
info  IPv6: normal path and bypass via en0
ok    bypass works for api.partner.example over IPv6

If the bypass cannot work, the connection fails. It is never sent through the VPN instead.

What happens to a connection

Three decisions, made separately: a tunnel can be decrypted and still go through the VPN, or pass through untouched and still be bypassed.

Who opened it

wraith asks the kernel which process owns the client's socket. A process under launchd_sim belongs to a simulator; a helper inside an .app belongs to that app. A connection from your Wi-Fi is a device you set up.

Decrypt or not

Inside the source, simulator traffic is decrypted with wraith's own CA. Mac apps are decrypted only if you made the Mac trust it. Pinned apps and hosts on no_decrypt pass through.

Which route

Bypassed hosts use DNS and sockets bound to the physical interface. Everything else takes the normal path, through the VPN if one is up.

Careful with your Mac

A proxy that decrypts HTTPS holds real power. wraith keeps it on your machine and in your hands.

Proxy settings come back

Saved before any change, restored on exit, Ctrl-C or a crash. wraith stop always restores them.

The CA stays on your Mac

Created here, key mode 0600, never exported. Simulators trust it; the Mac only if you run wraith ca trust --mac.

Nothing on disk

Captured flows live in memory and are gone when wraith stops. Only an export you ask for writes a file.

Secrets redacted

Exports and log lines hide Authorization, cookies and token headers and query parameters by default.

Fail closed

A bypassed host that cannot be reached directly fails. It is never sent through the VPN instead.

Local only

Listens on 127.0.0.1 and ::1; with --device also on your Wi-Fi address, for the devices you set up only. Verifies every upstream certificate and makes no network calls of its own.

Start in a minute

macOS 13 or later, Apple Silicon or Intel. Xcode for simulators.

  1. Install

    With Homebrew, which builds it on your Mac.

    brew install esuEdu/tap/wraith

  2. Boot a simulator

    Any iOS simulator. wraith puts its CA into each one as it boots.

    xcrun simctl boot "iPhone 17" && open -a Simulator

  3. Start wraith

    It sets the system proxy and opens the live view. Use your app and watch its requests arrive.

    wraith start

  4. Stop

    Press q or Ctrl-C. Your proxy settings are restored.
